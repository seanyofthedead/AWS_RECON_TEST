# Second-tier fixes against the October 3 review

October 5, 2026. This addresses the findings that [the first-tier pass](2026-10-04-first-tier-fixes.md) left open: F07, F12, F17, F18, F19, F22, and F23 from [findings.md](2026-10-03/findings.md). The scope is still the mock provider. This repository has no backend, so findings that need a server are hardened in the browser where possible and otherwise documented.

## Status by finding

| Finding | Status | Change |
| --- | --- | --- |
| F07 Posting period and reversal | Fixed for the demo | Entries carry the service period, posting period, effective date, and federal fiscal year separately (`src/utils/fiscalCalendar.ts`). The service period comes from a source `ServiceDate` when the data has one; the fixtures do not, so it is inferred from the posting date and every entry says so. A closed service period is never backdated: the entry posts on the first day of the first open period and is flagged as a prior-period adjustment that needs approval. Accrual templates schedule a reversal for the first day of the next period. Period status comes from a demo calendar that closes FY2025, not from an agency close schedule. |
| F12 Authoritative audit trail | Partially fixed | Decisions record the signed-in user's email and identity-provider subject instead of "UI Analyst". Each case has a version (its count of recorded decisions, read fresh from storage), and a decision made on a stale view, such as a second tab, is rejected instead of overwriting. The version check and the append run together with no await between them, and in browsers that support the Web Locks API they are serialized across tabs, so two submissions on the same version cannot both be recorded. History stays append-only. Decisions still live in browser storage, so they are not an authoritative audit trail, and prepare/approve separation does not exist. Both need a server. |
| F17 Identifier and variance lineage | Fixed for the demo | Transactions keep the immutable source transaction and vendor IDs beside their display aliases, and the quantity difference separately from the monetary variance. Match evidence was keyed on the display alias and now uses the source ID. The case page shows the source IDs and quantity difference and labels vendor names as demo display names. |
| F18 Silent ingestion repairs | Fixed | Transaction rows are validated (`src/utils/ingestion.ts`). Malformed or missing amounts, variances, and confidence values and missing or invalid dates are rejected with reasons, out-of-range IDs are rejected instead of dropped, and duplicate IDs are reported as exceptions. Counts and amounts reconcile across accepted, rejected, and duplicate rows. A failed fetch raises an error instead of yielding an empty file, and parser errors are reported. The Settings page shows the baseline report and, once imported, the batch report. The canonical file's duplicate IDs are still only warned about in development. |
| F19 Fixture coverage | Partially fixed | A test matrix covers all 15 root causes with positive, negative, zero, and missing-input variances (`tests/templateMatrix.test.ts`). The fixtures now include a confirmed match, reference and amount failures, a negative variance, and missing receipts. Scenarios such as credit memos, multiple receipts, split lines, multi-currency, and returns are not in the fixtures, and none of the expected outcomes has been approved by an accounting owner. |
| F22 API authentication and backend controls | Open (outside this repo) | Committed source has no API client and there is no backend, so bearer tokens, authorization, idempotency, and response validation cannot be checked here. Asset protection was checked: on October 5, 2026 the staging site served `/data/ui_transactions.csv`, `/data/canonical_variances.csv`, and `/evidence/CASE-00038/GL_Posting.pdf` with HTTP 200 and no sign-in. Sign-in protects the app's pages, not its static files, so sensitive data must not be placed in `public/`. |
| F23 Evidence regeneration | Partially fixed | The deprecated generator (wrong file names, 30-case default), its npm scripts, the `pdfkit` dependency, and its unused output (30 `CASE-TX-*` folders and two `evidence_index.json` files) are removed. `public/evidence/manifest.json` lists each case's four contract documents with SHA-256 hashes. Tests check it against the app's evidence links and the committed files, and check the documents' contents against the CSVs. The generator that produced the current PDFs is still not in the repository, so a clean-room regeneration is not possible. |

## Open decisions

- Vendor display names: resolved. The app showed names of real federal contractors for placeholder vendor IDs, while the evidence PDFs named one fictional supplier for every vendor. Both now use the same fictional name per vendor ID, built from Microsoft's fictitious company names, and a test checks every case's invoice, PO, and GL documents against the name on screen.
- Prior-period approval and the period close schedule need an accounting owner.
